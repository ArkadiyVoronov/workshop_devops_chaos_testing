# Пример 1: Manual vs IaC подход

## 🎯 Что проверяем

Демонстрируем разницу между:
- **Ручным управлением** (через консоль облака/CLI команды)
- **Декларативным подходом** (Terraform конфигурация)

## 📋 Сценарий

Создаём простую инфраструктуру:
- 1 виртуальная машина
- 1 группа безопасности
- 1 хранилище S3/blob

### Ручной подход (manual-steps/)

В папке `manual-steps/` описаны шаги, которые нужно выполнить вручную:
1. Зайти в консоль облака
2. Создать VM с определёнными параметрами
3. Настроить security groups
4. Создать storage account

**Проблемы подхода:**
- ❌ Нет версионирования изменений
- ❌ Человеческий фактор (можно забыть шаг)
- ❌ Сложно воспроизвести точно такую же инфраструктуру
- ❌ Неидемпотентно (повторное выполнение может создать дубликаты)

### Terraform подход (terraform-config/)

Один файл конфигурации описывает всю инфраструктуру:

```hcl
resource "null_resource" "vm_example" {
  # Имитация создания VM
}

resource "null_resource" "security_group" {
  # Имитация security group
}

resource "null_resource" "storage" {
  # Имитация хранилища
}
```

**Преимущества:**
- ✅ Конфигурация в Git (версионирование, code review)
- ✅ Один команда `terraform apply` создаёт всё
- ✅ Идемпотентность (повторный запуск не меняет результат)
- ✅ State file отслеживает текущее состояние

## 🔍 Ключевая концепция: Идемпотентность

**Идемпотентность** = многократное применение даёт одинаковый результат

```bash
# Запускаем первый раз
terraform apply  # Создаёт ресурсы

# Запускаем второй раз
terraform apply  # "No changes" - ничего не меняется

# Запускаем десятый раз
terraform apply  # Всё так же "No changes"
```

## 🚀 Запуск примера

```bash
cd terraform-config
terraform init
terraform plan
terraform apply -auto-approve
terraform destroy -auto-approve
```

## 📝 Ожидаемый результат

После `terraform plan` вы увидите план создания 3 ресурсов.
После повторного `terraform plan` - "No changes", что демонстрирует идемпотентность.
